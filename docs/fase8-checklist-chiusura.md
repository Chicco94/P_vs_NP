# Fase 8 - Checklist di chiusura

## Obiettivo

Questa fase serve a verificare la coerenza del repository e preparare il materiale finale da condividere, evitando documenti incompleti o incoerenti tra codice, report e presentazione.

## Checklist finale

- [ ] Verifica della documentazione generale
- [ ] Pulizia del codice e organizzazione delle cartelle
- [ ] Controllo della coerenza tra report, repository e presentazione
- [ ] Preparazione del materiale finale da condividere

## Verifica di documentazione

Il repository deve avere:

- README chiaro e coerente con il lavoro svolto;
- TODO aggiornato alle fasi completate;
- AGENTS.md coerente con i custom agents;
- documenti per ogni fase del progetto;
- riferimenti a file e cartelle corretti.

## Pulizia del repository

- eliminare file temporanei e artefatti non necessari;
- mantenere solo contenuti finali e rilevanti per il progetto;
- assicurarsi che i file JSON e Markdown siano leggibili e strutturati.

## Coerenza tra report e repository

Il materiale finale deve essere coerente con i seguenti assunti:

- il progetto non pretende di dimostrare un risultato impossibile senza evidenza;
- la classificazione dei risultati distingue bene teoria, casi speciali, approssimazione ed empiria;
- i limiti metodologici sono chiaramente espressi.

## Materiale finale da condividere

Il repository deve poter essere presentato con:

- una breve introduzione al problema;
- una descrizione della metodologia;
- una lista di evidenze chiave;
- una sintesi dei risultati principali;
- una chiara dichiarazione dei limiti e delle prossime prospettive.

## Nota finale

La chiusura del progetto non consiste nell'affermare una conclusione definitiva senza fondamento, ma nel lasciare un corpus coerente, verificabile e pronto per la discussione scientifica o per uno sviluppo successivo.
